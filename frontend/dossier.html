技术附件

卷宗记录的不只是产出，还有产出背后那套可复核的机制。

技术附件FILE 07 · ANNEX
编排　LangGraph 主从：主控识别意图、拆解任务、路由给专项角色，以「规划 — 执行 — 校验」闭环推进，单轮最多 3 跳以防回环。 检索　PostgreSQL + pgvector：向量、关键词与相邻句窗三路召回，RRF 融合后交叉编码器精排，引用可溯源到原文段落。 会话　Redis：短期记忆滑动窗口、限流窗口、三态熔断状态与分布式锁，多实例共享同一份治理视图，执行状态可恢复。 底座　Ollama 本地推理：对话模型 + bge-m3 向量化 + 重排，全程可离线，不依赖云端 API，也不产生调用费用。 工具　14 个统一纳管：RBAC 鉴权 → 滑动窗口限流 → 三态熔断 → 三级容错（重试 / 降级 / 人机兜底）→ 分布式锁 → 审计留痕 → 行为观测。

确认机制FILE 09 · SIGN-OFF
产出需确认　关键节点主动发起确认，生成内容以「待采纳」状态呈现——采纳才落稿，不满意就重生成。未经采纳的产出永远停在草稿态。 全链路留痕　意图识别、路由决策、工具调用与耗时完整落库，可逐条回放。审计写库与 Redis 解耦，基础设施故障也不会丢掉安全记录。 记忆沉淀　选题结论、论文大纲、写作约束与章节进度沉淀为结构化项目档案，跨会话延续，下一章接着上一章写。 降级边界　Redis 不可用时：对话链路降级跳过（能聊但无上下文），登录限流放行，工具调用按 fail-closed 拒绝并留审计——保护与可用性各有取舍，不静默。
