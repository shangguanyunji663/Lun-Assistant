五个乐章，一条旋律

视口中间的虚线是演奏指针：往下滚，指针扫过哪里，哪里的音符就被奏响。 每个音符都值得一按：它会出声，也会把注解写进右下角的批注签。

延长记号，就是你的裁决权

乐谱里，延长记号停多久由指挥决定。论匠把同样的权力交给你：确认条上四个动作，编队按你的拍子继续。整支编队停下来等一个人，这个设计是故意的。

配器表

一支编队要出声，靠的不是一件乐器。全部本地运行，断网也能排练。

编排LangGraph 主从编排：主控识别意图、拆解任务、路由给专项角色，以「规划 — 执行 — 校验」闭环推进，单轮最多 3 跳以防回环。
检索PostgreSQL + pgvector：向量、关键词与相邻句窗三路召回，RRF 融合后交叉编码器精排，引用的每一段都能溯源到原文。
会话Redis：短期记忆滑动窗口、限流窗口、三态熔断状态与分布式锁，多实例共享同一份治理视图，执行状态可恢复。
底座Ollama 本地推理：对话模型 + bge-m3 向量化 + 重排，全程可离线，不依赖任何云端 API，也不产生调用费用。
工具14 个工具统一纳管：RBAC 鉴权 → 滑动窗口限流 → 三态熔断 → 三级容错（重试 / 降级 / 人机兜底）→ 分布式锁 → 审计留痕 → 行为观测。

指挥权在你手里

多智能体最容易失控的地方是「自作主张」。论匠把拍子交给写作的人。

产出需确认

关键节点主动发起确认，生成内容以「待采纳」状态呈现——采纳才落稿，不满意就重生成。未经采纳的产出永远停在草稿态，不会悄悄写进正文。

全链路留痕

每次执行的意图识别、路由决策、工具调用与耗时完整落库，可逐条回放。审计写库与 Redis 解耦——基础设施故障也不会丢掉安全记录。

记忆沉淀

选题结论、论文大纲、写作约束与章节进度沉淀为结构化项目档案，跨会话延续。下一章接着上一章写，不用每次重讲一遍背景。
