# 论匠文档 · 统一格式规范（FORMAT STANDARD v1）

> 本文档为论匠全项目 Markdown 文档的统一格式规范（**文档域无关**，前后端通用）。
> 制定日期：2026-09-02 · 适用范围：`docs/` 全部文档、`docs/frontend-versions/` 前端版本线文档、根目录设计资产文档。
> 依据：用户 2026-09-01 定的「前端 MD 文档更新约定」+ ROUND4-6 落档形态 + v11/v12 设计稿 CHANGELOG 形态，归纳为一套可执行规范。

***

## 一、文档分类与目录归属（归类逻辑）

| 文档域               | 归类                                            | 存放目录                      | 典型文档                                          |
| ----------------- | --------------------------------------------- | ------------------------- | --------------------------------------------- |
| 前端版本线             | **frontend-versions**                         | `docs/frontend-versions/` | ROUND7-11 / DESIGN\_SPEC / CHANGELOG-v11/v12  |
| 后端工程线             | backend                                       | `docs/`                   | ROUND2 / ROUND4 / ARCHITECTURE\_REVIEW        |
| 混合轮次（前端小节 + 后端主体） | **main-location 归后端 / frontend-versions 挂指针** | 原位保留于 `docs/`，文档头加归属标注    | ROUND1 / ROUND3 / ROUND5                      |
| 通用治理线             | general                                       | `docs/`                   | ROUND6 / PROJECT\_STRUCTURE / LEARNING\_GUIDE |
| 部署运维线             | ops                                           | `docs/`                   | DEPLOY                                        |
| 设计稿资源（非 md）       | assets                                        | `design-concepts/`        | preview\.html / tuner.html / \*.png           |

> **归类判定规则**：内容主体 >50% 为前端版本/主题演进的 → frontend-versions；主体为后端功能/架构 → backend 线留 `docs/` 根；同时含前后端的轮次文档 → 按主体保留在 `docs/`，但其前端小节在文档头明确标注「前端小节归属 frontend-versions」。

***

## 二、文档头（Front-matter 元信息）统一格式

所有文档必须在 H1 标题后、正文前，用「引用块」写元信息头，**字段命名固定为以下 6 项**，顺序不可调换，缺失项填 `—`：

```markdown
# 论匠<域> · <标题>

> 文档域：frontend-versions | backend | general | ops        （四选一，必填）
> 文档类型：轮次记录 | 版本变更 | 设计规范 | 提案 | 审查报告 | 操作手册 / 指南    （六选一）
> 主题版本：v9 / v10 / v11 / v12 / —                          （版本线文档必填，其余 —）
> 轮次：ROUND7 / ROUND8 / … / —                               （轮次文档必填，其余 —）
> 日期：YYYY-MM-DD
> 状态：已落地 | 提案 | 已归档                                （三选一）
```

**示例（v11 CHANGELOG 头，迁移到 frontend-versions 后）：**

```markdown
# 论匠前端 · v11 四主题重构 — 变更文档

> 文档域：frontend-versions
> 文档类型：版本变更
> 主题版本：v11
> 轮次：ROUND8 关联（设计稿侧）
> 日期：2026-09-01
> 状态：已落地
```

## 三、H1 标题命名规则

| 文档域           | 标题格式                       | 示例                                       |
| ------------- | -------------------------- | ---------------------------------------- |
| 前端版本线 · 轮次    | `# 论匠前端 · 第 N 轮修改 · <主题>`  | `# 论匠前端 · 第十一轮修改 · B 主题由「水墨留白」翻转为「黑白瑞士」` |
| 前端版本线 · 变更    | `# 论匠前端 · vN <主题> — 变更文档`  | `# 论匠前端 · v12 B 主题黑白瑞士 — 变更文档`           |
| 前端版本线 · 规范/提案 | `# 论匠前端 <版本> · <主题>（<类型>）` | `# 论匠前端 v9 · 青绿长卷（放松版）设计规范`              |
| 后端 / 混合 / 通用  | `# 优化记录 · 第 N 轮（<主题>）`     | `# 优化记录 · 第六轮（架构改进与工程化治理）`               |
| 其他专业文档        | `# 论匠 · <主题>`              | `# 论匠 · 部署指南`                            |

## 四、章节结构与标题层级

1. **H2 章节一律用汉字数字编号**：`## 一、` `## 二、` `## 三、` …（不使用「## 背景 / ## 本轮改进明细」等自由命名）。
2. **H3 小节一律用阿拉伯数字点分**：`### 1.1` `### 2.3`；**最多两层**（H2 → H3），禁止 H4。
3. **前置约定章节（若适用）固定靠前**：

   - `## 一、总览（结论先行）`（版本变更 / 轮次文档，若正文长则压缩为表格）

   - `## 二、文件级变更摘要`（列：文件 / 改动 / 行号范围 / 类型：新增|修改|删除）

   - `## 三、具体改动要点`（每个 token / 字段用代码引用，附 file:line 证据）

   - 尾部固定章节：

     - `## N-2、与之前几轮 / 相邻版本的关系`

     - `## N-1、已知边界 / 未覆盖项`

     - `## N、追溯 / 关联文档`
4. **跨文档链接统一相对路径**：`docs/` 内互链用相对路径（如 `[ROUND11](../frontend-versions/OPTIMIZATION_ROUND11.md)`），旧路径的迁移 stub 已清理，链接一律指向新位置。

## 五、字段命名与措辞统一

| 术语            | 统一写法                                           | 禁用写法                              |
| ------------- | ---------------------------------------------- | --------------------------------- |
| 轮次            | `ROUND{N}`（如 ROUND11）                          | `round 11` / `第十一轮（无ROUND前缀）` 混用  |
| 版本            | `v{N}`（如 v12）                                  | `版本 12` / `V12`                   |
| 主题切换 tab      | `主题切换 tab` / `.theme-tabs`                     | `主题标签`                            |
| 前端/后端 目录      | `frontend/` / `api/ services/ infrastructure/` | —                                 |
| 主/次/低强调 token | `--jade / --pine / --seal`                     | 混用 `--gold` 指代强调（gold 仅 D 主题金泥专用） |
| 背景图           | `--ink-bg-url` / `ink-photo`                   | `bg-图`                            |

## 六、排版风格

1. 表格必须有表头分隔行 `|---|---|`，单元格内不放超长行。
2. 行号引用固定 `file:line`（如 `styles.css:121`），或在表格列里写「文件:行号」。
3. 代码片段用围栏 fenced block 且标注语言（`css` / `jsx` / `html`）。
4. 列表：无序列表用 `-`，有序列表与章节编号同步（不混用）。
5. 变更/警示统一用引用块 + ⚠️ 前缀，格式：

   ```markdown
   > ⚠️ **变更标注（YYYY-MM-DD）**：<变更说明 / 指向最新文档>
   ```

***

## 七、变更标注约定（本规范 V1 引入）

- 当文档被整理/迁移/修正而内容本身不变时，在原位置加一条「⚠️ 变更标注」，指明去向与理由。

- 当文档内容与事实冲突（如 ROUND10 声称"不再拆分 ROUND11"但 ROUND11 已落地）时，**不删原文**（保留历史），以变更标注形式说明，并指向权威文档。

- 统一前缀：「⚠️ **变更标注（日期）**」。

***

## 八、新文档快速套用

- **新增前端版本** → 复制 `docs/frontend-versions/TEMPLATE.md` 为 `CHANGELOG-v{N}.md`，按 §二/§四 填空。

- **新增后端/通用轮次** → 复制 `docs/OPTIMIZATION_ROUND{N}.md` 骨架（取 ROUND6 形态：`## 一、本轮改进总览` 开头），套 §二 元信息头。

- 每次新建文档后同步更新 `README.md` 文档导航表（保持两组：frontend-versions / backend-general）。

***

## 九、本规范自身演进

- 规范 V1 制定于 2026-09-02（文档治理轮）。后续如需修订规范本身，直接编辑本文档并在头部更新日期即可；不另立「规范版本」文档。
