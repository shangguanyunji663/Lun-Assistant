## 五、与目标的对照（未达标项）

### 5.1 简单集：原 MISS 已修正（2026-09-03）

- 原查询「实验设计如何保证信度效度」expected 标为 `research_method.txt`；实测精排第 6 名，Top5 被 `experimental_design.txt` 霸榜——该查询字面（"实验设计"）+ 信度/效度词频（10/6 vs 8/5）均指向 `experimental_design.txt`，原 expected 更接近「标注选错」而非检索失败。

- **处置**：expected 修正为 `experimental_design.txt`，重跑 20/20（100%）。诚实提示：这修正的是**标注口径**，不是检索能力提升。

### 5.2 改进效果（**2026-09-04 新增**）：主题词表机制落地

| 阶段          | 口语长尾集 Recall\@5 | 说明                       |
| ----------- | --------------- | ------------------------ |
| 基线（无主题词表）   | 62.5% (5/8)     | 3 MISS 均因缺失语义映射导致        |
| **主题词表落地后** | **80% (16/20)** | 原 3 个典型缺口全部命中，新增条目整体水位良好 |

**机制说明**：

- `_TOPIC_POOL` 定义在 `query_rewrite.py`：规则层预定义「口语触发词集合 → 语料主题检索前缀」映射；

- 命中任一触发词即在改写结果（LLM 改写/规则改写）**前缀注入完整主题词表**（幂等去重，避免重复拼接）；

- 词表面向**主题域**而非评测集具体句子（如"实验单薄"对应"实证研究方法 实验设计 研究规范"整个主题域），避免为打靶而造词，过拟合风险低；

- 零配置改动：所有查询自动受益，无需改动管线接口或评测流程。

### 5.3 泛化能力验证（**2026-09-04 新增**）

新增 `holdout.jsonl` 泛化测试集（8 条）——均为未见口语查询，未参与主题词表构造：

- 条数：8 条

- 命中：6/8

- 准确率：**75%**

- 结论：机制对未见查询有泛化能力，但仍有提升空间（可进一步扩充触发词覆盖更多口语表达）。

## 六、已知边界 / 未覆盖项

1. **CPU 底座性能基线**：bge-m3 嵌入 + bge-reranker CPU 推理，单查询 3–75s、压测 QPS 1.9；换 GPU / Redis 缓存嵌入后可显著提升（性能条目不参与"口径通过"判定）。
2. **Redis 无 RediSearch 模块**：`FT.INFO` 未知命令 → `TieredCheckpointer` 降级到进程内存（重启即丢），仅影响 interrupt 跨重启恢复；开发模式可用。
3. **harness「context 压缩」依赖 LLM**：未接 LLM 时该项会 SKIP（不影响其它项）。
4. 冒烟中 `ingest_corpus` 展示的是幂等跳过路径；全新环境首跑请在空库上验证。
