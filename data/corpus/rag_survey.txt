# 检索增强生成技术综述：架构、优化与评测
# 高翔 韩雪萤 软件学报 2024
一、引言：从参数记忆到外挂知识
检索增强生成（Retrieval-Augmented Generation，简称 RAG）通过在生成前引入外部知识检索，显著缓解大语言模型面临的知识时效性不足、专业领域知识缺乏与幻觉问题，已成为知识密集型应用的基础架构。大模型把海量知识隐式编码于参数之中，但存在知识截止时间、长尾知识覆盖不全、无法更新等固有局限；RAG 把"凭记忆作答"转变为"基于检索证据作答"，让模型既能利用生成能力，又能借助外部知识库获得准确、可溯源、可更新的答案。本文将从 RAG 的系统架构、检索技术、精排与知识融合、生成与评测、前沿方向与安全等维度，对检索增强生成技术进行系统综述。
二、RAG 的四阶段架构
典型 RAG 系统由查询理解、检索、知识融合与生成四个阶段组成，各阶段各司其职、环环相扣。
查询理解阶段对用户原始问题进行改写、扩展与分解，将口语化、碎片化的提问转化为适合检索的结构化查询。常见操作包括：对问题进行句法规范化与实体抽取；对含糊问题做扩展与澄清；将复杂问题分解为若干子查询。查询理解的质量直接决定了后续检索能否命中关键证据。
检索阶段从向量库、倒排索引或知识图谱中召回候选证据。它负责把"问题"与"文档"进行相关性匹配，是 RAG 的引擎所在，召回质量决定了系统的知识上限。
知识融合阶段对候选证据进行去重、排序与压缩，从海量候选片段中筛选出最相关、信息密度最高的上下文。该阶段通常包含精排、去冗余、上下文组装等环节，直接影响生成时的信息质量与上下文长度。
生成阶段基于检索得到的证据进行忠实作答并标注引用来源。良好的生成阶段应做到"有据可依"：每个论断能对应到证据片段或引用编号，并在证据不足时坦诚表明而非编造。
三、查询理解：让问题更适合检索
查询理解是 RAG 中常被低估却极为关键的环节。原始用户问题往往语言随意、指代模糊，直接用于检索可能造成被动召回下降。改写查询的常见技术包括：利用大语言模型把问题改写得更完整、更正式；将口语化表达转换为包含关键实体的规范表述；对多义词结合上下文消歧；以及把宽泛问题拆解为多个焦点更明确的子查询。
实践中，查询改写对长尾复杂问题的召回提升十分显著。例如"帮我讲讲那个去年发的、被引很多的论文"这种指代词极强的问题，若不改写几乎无法检索；而改写为包含作者名或关键词的规范化查询后，检索命中率大幅提高。实现层面，改写通常由一个小型 LLM 或专门模型完成，既可与主模型复用，也可独立部署以降低成本与延迟。
四、稀疏检索与稠密检索两条路线
检索技术沿稀疏检索与稠密检索两条路线发展，各有优势与局限。
稀疏检索以 BM25 为代表，基于词频与逆文档频率进行相关性打分，对术语精确匹配场景表现稳健。BM25 不依赖训练数据、可解释性强，在专有名词、缩写、代码标识符等"精确匹配"需求场景中依旧可靠；在中文场景下通常配合 jieba 等分词器使用，中文分词质量会直接影响其检索效果。
稠密检索通过双编码器将查询与文档映射到同一向量空间，以余弦相似度召回语义相关内容，代表模型包括 BGE、GTE 与 E5 系列。稠密检索能够捕捉同义改写、语义相近但字面不同的话语，因而在开放式、语义性问题上表现更好；但它需要向量索引与相当的计算资源，对长文档的表示也仍存在信息压缩带来的损失。
在实际系统中，两者往往互补：稀疏检索强于精确与术语，稠密检索强于语义与泛化，单一路线都难以全面覆盖真实查询分布。
五、混合检索与倒数排名融合
为兼收两路之长，混合检索将稀疏检索与稠密检索的输出合并。合并方式主要有两类：倒数排名融合（RRF）与加权分数融合。
RRF 的思路极为简洁而稳健：对来自多路检索结果的每个候选，根据其在各路由单的排名计算融合分数——排名越靠前，贡献越高，而无需校准各路的原始分数尺度。RRF 天然规避了"不同模型分数不可比"的问题，是生产环境中最常用的融合方式，实测相比单路检索可将 Recall@5 提升五到十个百分点。
加权分数融合则要求把各路的相似度或相关性分数映射到可比较的尺度后再加权求和，需要额外的分数归一化处理，对实现细节敏感。除 RRF 外，还有基于学习的方法（如等权线性组合、可学习的权重或重排器）进一步融合多源信号。混合检索已成为高质量 RAG 系统的事实标准配置。
六、精排与漏斗式架构
召回的目标是"不漏"，精排的目标是"准"。检索阶段通常只求快速召回一个较大的候选集（如数十至上百条），再交由精排环节精确打分排序。
精排阶段使用交叉编码器对查询与候选片段进行深度语义交互打分，代表模型为 bge-reranker 系列。与双编码器各自独立编码不同，交叉编码器将查询与候选拼接后一同送入模型，能够捕捉二者之间丰富的交互特征，排序精度显著更高，但计算开销也大得多。
因此生产环境普遍采用漏斗式架构：先用轻量召回缩小候选集至数十条，再对这部分执行精排。这种"先召回、后精排"的组合在精度与延迟之间取得平衡，是当前主流实践。此外，精排结果还可用于为生成阶段组织上下文顺序，把最相关证据放在模型更容易关注的位置。
七、知识融合：去重、压缩与上下文组织
检索得到的候选片段往往存在大量冗余：同一信息可能以相似表述出现在多个文档中。若不加处理送入生成模型，冗余会稀释注意力、挤占上下文窗口，甚至引入相互矛盾的内容，产生"上下文噪声"。
知识融合阶段承担三道工序。其一是去冗余，通过语义相似度或聚类剔除信息高度重叠的重复片段。其二是压缩，将冗长片段截取、改写或摘要为信息密度更高的简洁上下文，以节省 token 预算并提升关键信息的突出度。其三是上下文组织，决定哪些证据进入、以何种顺序排列，使模型能够高效利用。实践的印证是，知识融合阶段的冗余去重可有效降低生成阶段的上下文噪声，进而提升答案的忠实度与相关性。
八、生成与忠实性控制
生成阶段的目标是在检索证据的约束下输出准确、忠实、可溯源的答案。这里的核心挑战是"忠实性"：模型应基于证据作答，而非"旧习复发"地凭借记忆自由发挥。
提升忠实性的手段包括：在提示中明确"只依据给定材料作答、不确定时说明"；要求回答标注证据编号或引用，使每个论断可回溯；把证据划分为结构化块并以编号形式注入上下文。当证据不足时，系统的正确行为应是诚实声明"未检索到可靠依据"或建议补充检索，而不是凭空编造。
生成质量与检索质量的平衡也是一个持续课题：证据不足时强行作答容易产生幻觉，证据过杂时又可能被无关信息带偏。因此生成阶段往往与前序各阶段联动，必要时根据生成质量反馈触发补充检索，形成闭环。
九、评估指标体系
评测是驱动 RAG 系统不断优化的标尺。RAG 系统的指标分为检索质量与生成质量两类。
检索侧采用 Recall@K、MRR 与 NDCG。Recall@K 衡量前 K 个召回结果中真正相关文档的覆盖比例，MRR 重视第一条相关结果的排序位置，NDCG 则结合相关性分级评估排序质量。这些指标共同刻画召回与排序的双重能力。
生成侧重点衡量忠实度、答案相关性与引用准确率。忠实度判断回答中的关键论断是否能在检索证据中找到支撑；相关性评估回答是否切题回答了用户问题；引用准确率检验回答所标注的引用是否真实存在且位置正确。对知识型问答而言，忠实度与引用准确率往往比单纯的文本相似度更能反映真实可用性。
十、RAGAS 等自动化评测框架
传统评测依赖人工标注，成本高、规模受限。RAGAS 等自动化评测框架利用 LLM 作为裁判，在不依赖人工标注的情况下估算上述指标，显著提升评测的自动化程度与可扩展性。
RAGAS 将检索与生成质量拆解为可计算的子指标，如 context precision、faithfulness、answer relevancy 等，通过向评测 LLM 构造结构化的打分任务来自动获得分数。这类框架面临的共同挑战是"裁判偏见"——LLM 打分可能偏好多变的长文本、受到顺序与表述的影响，因此实践中建议对回答做"逐声明拆解"后逐一判断，并辅以少量人工抽检校正。
自动化评测的价值在于可持续回归：每次调整检索、改提示、换模型后，都能快速比较指标升降，防止为提升单项指标而牺牲整体质量。
十一、自适应检索与迭代检索
前沿研究正从"单轮检索生成"走向更灵动的检索策略。
自适应检索根据问题难度动态决定是否检索、检索多少次。简单且模型有把握的问题可以省去检索以降低延迟，困难问题则必然走完检索链路；系统通过问题复杂度评估或置信度信号触发分级处理。
迭代检索则采用多轮"检索—生成—再检索"的策略逐步逼近答案。第一轮检索可能不足或偏离，模型依据中间结果生成"存在什么缺口"的判断，再据此发起补充检索，直至证据足够。另一种形式是"检索即工具"设定：把检索封装为模型可自主决定何时调用的工具，用于多跳推理、事实核对与实时信息补取。这些策略在于让 RAG 更智能化地分配计算资源、逼近更可靠的答案。
十二、面向多智能体系统的工具化检索
随着 Agent 技术的兴起，检索被进一步封装为可被智能体调用的受治理工具。在这种设定下，检索不再局限于固定的生成链路，而是成为智能体规划与行动的一部分：智能体可在推理过程中自主发起检索、整合多源证据、对结果做交叉验证，并把结论回填到任务执行流程。
工具化检索带来的治理问题包括：需要为检索工具定义清晰的权限边界与调用规范，防止不可控的循环检索；需要对检索结果做指令痕迹检测，防止夹带恶意指令的证据"污染"智能体的决策。将检索治理纳入智能体安全体系，是面向下一代应用的重要课题。
十三、安全与投毒攻击防护
RAG 系统将外部内容作为可信上下文注入，这一特性带来新的安全面，需要高度重视知识库投毒与检索结果注入风险。
投毒攻击指向知识库中注入精心构造的恶意内容，使检索结果引导模型输出错误、偏颇或有害的信息。由于 RAG 默认采信检索到的内容，一旦攻击者成功投毒，模型会"心甘情愿"地放大这些错误，甚至比模型自身幻觉更隐蔽。防护手段包括对入库内容实施来源审计、优先级评级与内容过滤，并对高风险用户生成内容设置独立的入库审核通道。
检索结果注入则指攻击者把恶意指令伪装成文档内容，诱导模型越权或泄露信息。应对策略是对检索内容做指令痕迹检测、对输出做安全审查，并将检索证据与系统指令在上下文中的边界做显式划分，降低"指令与证据混淆"的风险。
十四、选型与工程落地要点
落地一套生产级 RAG 系统，选型与工程细节至关重要。在向量库层面，需要根据规模与并发选择合适的索引结构（HNSW、IVF-PQ 等）并做调优，平衡召回精度与检索延迟；在嵌入层面，需预先批量计算文档嵌入并建立更新机制，保证新入库内容能被及时检索；在查询层面，配合缓存减少高频问题的重复检索开销。
更重要的是建立"评测—调优"的闭环：先搭建包含检索与生成指标的评测集，再针对暴露的短板定向优化查询改写、混合检索权重、精排模型与提示设计。没有可量化指标的调优如同盲人摸象，只有把指标与业务目标打通，RAG 系统的质量才能被稳定地度量与提升。
十五、常见失效模式与调优方向
实践表明，RAG 系统的问题常常不在生成模型本身，而隐藏于检索与知识融合链路上。识别这些失效模式对调优至关重要。
其一，检索层失效：所召回的证据与问题无关或过时，导致模型"基于错误证据"作答。排查时应检查查询改写是否到位、混合检索权重是否合适、向量库是否涵盖目标知识，必要时改进改写与召回。其二，分块与上下文组装失效：检索到正确证据却因分块把关键句切散、或被冗余内容挤占，使模型"看不到关键证据"。这需要调整分块大小、证据排序与上下文组织策略。其三，知识融合的噪声问题：候选集中夹杂少量无关或矛盾片段，诱导模型"跑偏"，应强化去冗余与按相关性重排。
调优方向通常遵循"先证据、后模型"的顺序：先通过评测定位是召回不足、排序不准还是生成不忠实，再对症下药。只有把失效点定位准确，混合检索权重的调整、精排模型的升级与提示的细化才能真正发挥作用，避免盲目调参带来的内耗。
十六、发展趋势与总结
RAG 正处于快速演进之中，未来趋势包括：检索、生成与验证的一体化整合，使系统在生成过程中持续自我校验；更强大的语义表示与更高效的精排模型，进一步压缩检索误差；以及与多智能体、工具调用深度耦合的下一代知识服务架构。
总结而言，RAG 通过"查询理解、检索、知识融合、生成"四阶段将外部知识与生成能力有机衔接，以混合检索保障召回、以交叉编码精排保障精度、以自动化评测保障质量，并在安全性上应对投毒与注入风险。它把大模型从"记忆富但可能出错"推向"有据可依、可溯源、可更新"的可靠知识服务形态，是知识密集型 AI 应用值得长期投入的技术方向。
